## Stage A intent routing

The built-in command, workshop and everyday handlers retain their ordering.
The intent table supplies canonical phrases, risk classes and voice help.
The installed owner can say “Turn on voice shortcuts” and confirm to
enable exact shortcut resolution for addressed turns the other handlers
and greeting leave unhandled. Reversible shortcuts reuse the normal handler. Stateful shortcuts
ask before acting. Memory writes, deleting a list, shutdown and guest-mode
changes use their explicit commands.

Say “When I say kill the lights, I mean dimmer” to offer a shortcut. A strict
yes saves the phrase. An exact suggestion to run a command is a separate
confirmation. “Forget my shortcut kill the lights” targets only that
shortcut. The archive keeps confirmed phrases as owner speech records
marked for operational use. Topic forgetting, expiry, backup and restore
follow the existing archive rules. Guests and session-only memory have no
shortcut storage. Shortcuts start off. “Turn off voice shortcuts” deactivates
saved shortcuts after confirmation. “Forget everything” removes the saved
shortcut records and the setting.

## Phrase, time and event habits

Say “New habit,” then “Habit trigger evening check.” Add up to six steps
with “Habit step dimmer,” “Habit step open the clock,” or another supported
command. Say “Save habit.” Pip reads back the trigger and every step, then
waits for a plain yes. “Run the evening check habit” is an explicit trial
run. After that, an addressed “Evening check” runs the same steps.

The initial step set covers time, date, battery, brightness, volume, Clock
and Monitor. Existing commands get first refusal on the trigger phrase.
Every step re-enters normal dispatch, so body and app guards still apply.
A step that needs confirmation stops the sequence. Guest mode and
session-only memory keep habits unavailable.
An addressed phrase habit can also read the owner's pending reminders for
today or tomorrow. The reminder reply stays out of captions and memory.

“What habits do you have?” lists saved triggers. “Stop the evening check
habit” and “Forget the evening check habit” ask for confirmation before
disabling or deleting it. Habits live in `lists.db`, so backup and
“Forget everything” include them. The installed slot must be confirmed
before writing habits. “Habit trigger every weekday at 7 am” adds a local
schedule. “Habit trigger when I stop my alarm” selects the acknowledged-alarm
event. Time triggers wait on clock doubt and quiet hours. A trigger missed
while the lid was closed is skipped with a local action entry. Event triggers
use a ten-minute cooldown and a six-run local-day cap.

An owner can also say “New habit when I say good night do dimmer then
open the clock.” The one-line form uses the same read-back and strict
confirmation as step-by-step setup. Care's Habits page shows the saved
trigger and every step and allows keyboard step editing, enable, disable
and deletion.

“Habit trigger when my backup drive is connected” applies to a new arrival
of the drive enrolled in Care. The remaining low-risk actions require the
same current enrollment and attached device at delivery. “Habit trigger
when I first talk to you today” uses the first addressed owner turn after
5 am. A pending first-words habit can wait through quiet hours or a restart
on the same trusted local day. Morning briefs and greetings keep their
independent schedules.

“Habit trigger when someone appears” requires the current camera permission.
The first observation after camera or lid state changes establishes a
baseline. A later, fresh absent-to-present change can run the explicitly
approved steps. It represents a person appearing. It carries no identity.

“Turn on habit suggestions” asks for a plain yes before keeping any
observations. Pip counts only consecutive allowlisted commands separated by
at most five minutes. Four distinct local days within the last seven can
qualify a pair. Shorter memory retention shortens the window. Pip can offer
at most one routine per day. The offer reads back both steps and a new phrase.
A plain yes saves it, and the saved phrase starts the routine later.
“Turn off habit suggestions” clears the local observations. They are outside
conversation recall, the action log and backup.

## Running the first Wave 1 measurement

Run `pip-diag workload` on the intended image. It writes aggregate counts from up to 512 route lines on the current boot and reads per-service CPU pressure directly from Linux. It separates model fallbacks, unavailable and waiting routes. The optional missed-local estimate uses the existing command-prefix check when voice debugging already provides words. Private, discarded and overheard routes are excluded. The report contains no transcript or audio, and unavailable readings appear as such.

Collect one idle sample and one during an ordinary exchange on the MacBook. Compare the same organs, and keep the sample command, image ID and boot context with the report. Use a labelled phrase set to measure true missed intents before making any automatic routing change. [Diagnostic reference](../manual/REFERENCE.md#diagnostics-pip-diag)

Run `pip-diag continuity` to inspect the life record and archive, verify both live cortex slots, compare the archive with its saved baseline, and check recall and forgetting using synthetic text in a RAM archive. A verified archive mismatch makes the diagnostic exit nonzero and names the failed comparisons. The installed boot health service also runs the comparison if a baseline exists. Installed trials must additionally pass the RAM recall fixture and the built-in phrase table from `pip-diag commands` before confirmation. On a confirmed slot, the service reports a continuity failure and leaves the face available. First installs and restores without a baseline still run the archive and live-slot checks. Changes to identity text and model fingerprints are diagnostic flags. Witness hashes and deletion references stay in the private baseline. The guards need signed update, restore and rollback rehearsals on the same image inputs. [Diagnostic reference](../manual/REFERENCE.md#diagnostics-pip-diag)
